# 六状态趋势划分

> **身份：读图对照，不改生产。** 生产买卖仍以 `hold_up` 为准。分类实现：`src/ashare_daily/lib/six_states.py` 的 `classify_six_states`。`ashare-daily listing` 默认把图12 画进 `{YYYYMMDD}_from_listing_stock`（`--no-fig12` 可关）。
>
> 状态名描述价格相对图7–图11 通道的位置。指标见 [路径说明.md](路径说明.md)。刀锋日怎么读，见 [防接飞刀_判断指标速查清单.md](防接飞刀_判断指标速查清单.md)。
>
> 这套优先级最初在八只 ETF 上对过覆盖率。那些占比、行情段和「一状态一动作」的表没有迁入：它们不是个股验证。个股上，状态仍然只回答「在哪」。

## 1. 六个状态的定义（严格因果，按优先级判定）

| 状态 | 判定条件 | 通俗含义 |
|---|---|---|
| ①过热 | 收盘触图9或图10 上轨 | 短期情绪极值 |
| ②急跌刀锋 | 连续 10 日收在 fig10（3 个月）路径之下 | 持续破位 |
| ③趋势下行 | fig10_g ≤ 0 且 fig9_g ≤ 0 | 中周期斜率双空。读作「下行已确认」，斜率滞后，见 §3 |
| ④底部修复 | 站上 fig10 路径，但 fig9/fig10 斜率未双正，且未满足⑤ | 止跌回升、趋势未确认 |
| ⑤趋势上行 | fig8_g > 0 且 fig9_g > 0 | 中周期双斜率共振向上。读作「上行已确认」，斜率滞后，见 §3 |
| ⑥震荡 | 以上都不满足 | 路径附近的混沌地带 |

`classify_six_states` 后写的条件盖住先写的：①过热 > ②急跌刀锋 > ③趋势下行 > ⑤趋势上行 > ④底部修复 > ⑥震荡。④和⑤可以同时满足，⑤盖住④。代码里的顺序是先铺⑥，再用位置和斜率一层层盖上去。

所有输入都是当日收盘可得的 trailing 量：`px`、`fig8_g`、`fig9_g`、`fig10_g`、`fig10_path`、`fig9_touch_hi`、`fig10_touch_hi`。无未来数据。fig10 路径还没算出来的日子标成「数据不足」。

## 2. 状态回答位置，不回答下一笔怎么做

①②④⑥用**价格位置**（收盘相对路径或上下轨），当天就能看见。③⑤用**斜率符号**（窗口里的对数趋势斜率），天然慢半拍：双 g 转正时，这段上涨往往已经走了一截；双 g 转负时，阴跌也已经走了一截。

因此：

- ③趋势下行应读作「下行已确认」，它否决「这只是噪音」，不是「今天还在跌」。
- ⑤趋势上行应读作「上行已确认」。看到⑤再进场，吃不到这段斜率形成之前的主升。生产买点仍是进入上涨态的绿三角，不是⑤。
- ①过热是短期极端，不是牛市顶专属。熊市反弹同样可以贴上轨，要配③/⑤的背景看。
- 边界日常见 1～2 天闪烁。读图时用持续天数过滤，不要单日改仓。

ETF 八品种上做过「每个状态空仓 / 半仓 / 满仓」的对照，结论是**没有跨品种唯一动作**：②在一部分品种上满仓更好，⑤在一部分品种上空仓更好。那个对照的名单和夏普差没有迁入。个股还没有同等测试。不要把状态名直接翻译成空仓或满仓。

## 3. HTML 上怎么认出状态

listing HTML 的图12 就是这六个状态。不看图12、只看图7–图11 时：

1. 先看收盘相对 fig10 路径和上下轨，定①②④⑥。
2. 再看斜率符号，定③⑤。`g` 是悬停里的「当日路径年化」，也可以看路径线近端是上翘、走平还是下弯。

符号的近似（用路径线回看，长度约为窗口的 2/3）：

```text
fig10_g ≈ (path_t / path_{t-42})^(252/42) − 1     （3 个月窗口 → 42 日回看）
fig9_g  ≈ (path_t / path_{t-63})^(252/63) − 1     （6 个月窗口 → 63 日回看）
fig8_g  ≈ (path_t / path_{t-126})^(252/126) − 1   （1 年窗口 → 126 日回看）
```

这是定义上的近似，不是个股上测过的一致率。g 在零附近时，③和⑤的边界日最容易看错；那几天的动作本来就该观望。

## 4. 和图12 的关系

`src/ashare_daily/plots/add_fig12_six_states.py` 在 listing HTML 上加干净 K 线加状态色带。它调用的就是 `classify_six_states`。色带不产生买卖点，也不改 `hold_up`。
